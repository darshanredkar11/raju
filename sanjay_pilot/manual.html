How to work with the sales agent

A practical guide for sales users: what the workspace can do today, how to give it reliable context, how to review its work, and what is not connected yet.

Important system status: this release uses a generic LLM API for assistant replies and draft generation. Harvey is not installed or connected in the current deployment. The agent cannot send emails or activate campaigns. Treat all generated recommendations as drafts that need human verification.

1. Start with product knowledge

Before asking for market recommendations or a product-specific buyer email, upload the latest approved catalogue, Technical Data Sheets (TDS) and Safety Data Sheets (SDS).

  • Open Documents.
  • Select the document type and a PDF.
  • Wait for the upload confirmation; duplicate files are detected.
  • Scanned/image-only PDFs need OCR before upload.

2. Ask precise questions

Give the agent a goal, geography, buyer segment and relevant constraints. Ask it to distinguish sourced facts from assumptions.

  • “Summarise the product range in the uploaded catalogue.”
  • “Research importers in Germany for the documented product range and cite evidence.”
  • “List missing facts before preparing outreach.”

3. Research markets

Open Market research, select relevant source documents, set the target region and buyer segment, then run research. The app searches external sources and asks the configured LLM to propose opportunities supported by those sources.

Every proposal should have a clickable evidence URL. Verify the original source, relevance, date and chemical/product fit before approving it.

4. Prepare buyer outreach

Ask the agent to draft a first-touch email and include the buyer email address and known company context. The app requires product source documents before generating a product-specific draft.

Check recipient, subject, claims, technical details and tone. Do not send unsupported claims about purity, certifications, compliance, price, stock or delivery.

5. Review approvals

Open Approvals. Review the evidence and exact content, then approve only when you are satisfied. The app records who created and approved the item.

Approval is not sending. Email delivery is disabled, and market proposals do not automatically launch a campaign.

6. Track daily work

Use Daily progress and the home dashboard to review chat activity, uploaded documents, research proposals and drafts. Refresh if a recent action is not visible.

How the current system is wired

1
Browser UI

Login page → Google OAuth session → authenticated FastAPI dashboard and protected API routes.

2
Application services

FastAPI routes validate requests, use MongoDB for records and GridFS for original PDF files, and keep chat history per signed-in email.

3
LLM provider and research

Chat and email drafting call the configured OpenAI-compatible chat-completions endpoint. Market research uses Tavily search plus the configured LLM. This is not Harvey's autonomous runtime.

4
Human approval boundary

Proposals and drafts remain pending until reviewed. There is no outbound email sender and no autonomous campaign execution.

Harvey runtime: not connected

To integrate Harvey properly, the owner must provide the intended Harvey product/runtime, supported API or SDK, authentication method, tool contract and deployment location. Do not set a made-up URL or treat an LLM API as Harvey.

Team operating rules

  • Never upload credentials, passwords, or unrelated personal data.
  • Use only approved product documents; check revision dates.
  • Do not treat AI output as a source of truth for chemical safety, regulatory status or export compliance.
  • Verify citations by opening the original source.
  • Do not use this pilot with confidential customer/pricing information until role-based access and workspace isolation are implemented.
  • Report incorrect outputs and record which source document was used.
